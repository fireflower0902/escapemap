# 사이트별 크롤러 검증

67개 `sync_*_db.py`를 실제 사이트에 **순차 요청**하고, Firestore 저장 대신 메모리에서 결과를 검사합니다. Firebase 키가 필요하지 않으며 운영 DB를 읽거나 변경하지 않습니다. 기존 지점의 메타데이터는 로컬 SQLite 파일을 읽기 전용으로 불러옵니다.

## 실행

`backend`에서 다음 명령을 실행합니다.

```sh
# 개별 사이트: 대표 지점, 오늘과 내일
uv run python scripts/check_crawlers.py keyescape --days 1

# 개별 사이트: 등록된 모든 지점
uv run python scripts/check_crawlers.py xdungeon --all-branches --days 1 --timeout 180

# 모든 크롤러를 하나씩 순차 실행
uv run python scripts/check_crawlers.py --all --days 1 --timeout 90

# 외부 통신 없이 수정 사항 회귀 검증
uv run python -m unittest tests.test_nationwide tests.test_crawler_regressions -v
```

전국 지역 분류 계약 테스트는 `frontend/node_modules/typescript`와 Node.js를 사용합니다. 프론트 의존성을 먼저 설치해야 합니다.

GitHub Actions의 **개별 크롤러 읽기 전용 검증**을 수동 실행해도 됩니다. `crawler`에 `xdungeon`, `keyescape` 또는 `all`을 입력합니다. 결과 JSON과 로그는 실행 artifact에 첨부됩니다. 오류·미확인 항목이 있으면 해당 실행은 실패로 표시됩니다.

## 판정 범위

- `smoke_pass`: 시간대가 수집됐고, 시간·상태·예약 URL·중복 여부·테마 연결 검사를 통과했습니다.
- `needs_review`: 0개 수집, 조회 경고, 비정상 HTTP 응답 또는 데이터 형식 오류가 있습니다. 0개가 곧 폐업이나 전체 마감을 뜻하지 않습니다.
- `error`: 크롤러 예외 또는 실행 실패입니다.
- `timeout`: 제한 시간 내 끝나지 않았습니다.

기본 실행은 지점 설정의 첫 항목만 대상으로 합니다. 공용 API나 브랜드 설정은 여러 매장을 한 번에 반환할 수 있습니다. `--all-branches`는 **코드에 등록된 지점 전체**를 뜻하며, 해당 브랜드에 새로 생긴 미등록 지점까지 포함한다는 뜻은 아닙니다. 일부 크롤러의 테마 메타데이터는 사이트 조회가 아닌 기존 정적 정의에서 생성됩니다.

통과는 전체 지점·전체 날짜 정상 동작, 원본 화면과 모든 시간대의 수동 대조, 실제 예약 성공 또는 Firestore 원격 쓰기 성공을 보장하지 않습니다. 마피아카페는 월 단위 API를 사용해 당월 전체가 포함되고, 지구별은 오늘만 조회할 수 있습니다.

## 전국 지원 변경

- 화면에서 전국·서울 전체·시도·기존 서울 세부 지역을 선택할 수 있습니다.
- Next.js/FastAPI 검색 모두 지역이 생략되면 전국을 조회합니다. 잘못된 지역은 HTTP 400으로 거부합니다.
- `supported_area=false`로 남은 비서울 카페도 검색합니다. 과거 `etc` 분류는 주소로 보완하므로 일괄 DB 수정 없이 검색할 수 있습니다.
- 자동 크롤링 설정은 `CRAWL_SEOUL_ONLY=false`입니다. 아직 배포/푸시하지 않은 로컬 변경이며 운영 작업에 적용하려면 배포가 필요합니다.
- `.env`에 쓴 `SKIP_META_WRITES`도 실제 적용하도록 설정 경로를 통일했습니다.

조회 시 활성 카페 목록을 읽어 주소로 지역을 분류합니다. 과거 데이터가 갱신되기 전에도 지역 누락을 피하기 위한 방식이며, 검색 응답의 기존 CDN 캐시는 유지합니다.

## 심야 시간

더코드·제트방탈출의 `24:10`은 영업일 다음 날 `00:10`으로 비교합니다. 저장값과 예약 링크는 사이트의 영업일·원래 시간 표기를 유지합니다. `24:00`~`29:59`를 지원하며 범위 밖 값은 경고 후 제외합니다.

## 결과 파일

- `verification-2026-11-14.md`: 이번 점검의 사이트별 최종 판정과 남은 확인 사항.
- `verification-2026-11-14.json`: 해당 판정의 구조화된 상세 결과.
- 실행마다 생성되는 개별 JSON·로그와 `latest-run.json`은 로컬 또는 Actions artifact로 확인합니다.

## 개발 현황판

프론트 개발 서버를 실행한 뒤 `http://localhost:3000/dev/crawlers`를 엽니다. 상단 **개발 현황판** 링크로도 이동할 수 있습니다. 개발 모드에서만 페이지와 API가 열립니다.

- **카페 현황**: 전국/지역별 목록, 운영 상태, 크롤러 매핑 여부, DB 미등록 지점, 선택 날짜의 저장 테마·시간대·예약 가능 수, 해당 지점의 테스트 집계를 확인합니다.
- **크롤러 검증**: 사이트별 최신 검증 상태와 실행 범위, 테스트 테마/시간대 수를 확인합니다. 실행 합계와 지점별 집계가 없는 옛 결과는 구분하여 표시합니다.
- **상세**: 저장된 테마 목록, 검증 시각, 오류 내용, 복사 가능한 실행 명령을 보여줍니다. **검증 실행**은 운영 DB 쓰기 없이 오늘·내일을 조회합니다. 대표 지점/등록 지점 전체 중 선택할 수 있습니다.
- **전체 크롤러 순차 검증**: 67개 크롤러를 하나씩 실행합니다. 다른 검증이 진행 중이면 중복 실행하지 않습니다.
- **새로고침**: Firestore를 다시 읽습니다. 1분 자동 확인은 DB 조회에 5분 캐시를 적용하고, 테스트 진행 중에는 결과 파일을 5초마다 다시 확인합니다.
- **CSV**: 현재 카페 필터에 해당하는 목록과 수치를 내보냅니다.

원본 데이터는 Firestore의 `cafes`, 활성 `themes`, 선택 날짜의 `schedules`에서 읽습니다. 지점 매핑은 `crawler_catalog.py --stdout`의 AST 분석 결과를 사용하므로, 코드에 지점을 추가하면 목록에 반영됩니다. Firestore가 연결되지 않으면 수치를 0으로 위장하지 않고 `—`와 오류 안내를 표시합니다.

화면에서 실행한 결과는 `dashboard/`에 저장됩니다. CLI 실행도 각 출력 폴더의 `history/`에 개별 이력을 남깁니다. 새로운 대표 지점 테스트가 다른 지점의 과거 검증 기록을 지우지 않도록 지점별로 가장 최근에 포함된 실행을 선택합니다. 테스트가 통과해도 운영 DB에 자동 업로드하지는 않습니다.

프론트 검증:

```sh
cd ../frontend
npm run test:dashboard
npx tsc --noEmit
```
